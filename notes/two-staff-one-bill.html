Cable Manager · 3 Nov 2026

Two staff, one bill

How two people pressing Record at the same moment could pay one bill twice, and why the fix was a lock rather than a better check.

In Cable Manager, staff record a payment by opening a bill and pressing Record. The code looked careful: it checked whether the bill was already paid, refused if it was, and only then wrote the payment inside a transaction.

The bug

The check happened before the transaction began, from a read that took no lock. If two staff pressed Record on the same bill at the same instant, both requests read the bill as unpaid, both passed the check, and both payments went in. The bill was paid twice, and the bookkeeping ledger with it.

Each request on its own was correct. Only the timing between two of them was wrong, which is why it never showed up when one person tried the feature, and why a quick fix to the check itself wouldn't have helped: any check made outside the lock can be out of date by the time the write happens.

The fix

The check moved inside the transaction, after locking the bill's row. In outline:

START TRANSACTION;
-- a second request waits here until the first one commits
SELECT amount, status FROM invoices WHERE id = ? FOR UPDATE;
-- already paid? roll back and refuse
-- otherwise record the payment and settle the bill
COMMIT;

Now the second person's request waits until the first one commits, then reads a bill that is already settled, and is refused. Whether the bill is fully paid is judged against the amount read under that lock, not an earlier copy.

Proving it

A race is easy to "fix" and hard to show fixed, so I wrote a test that makes it happen on purpose. A second database connection settles the bill and holds its lock for a second while the payment is recorded. On the old code the test fails, because the payment is written. On the new code it passes, and it now runs with the rest of the suite.

What I took from it

If a check decides whether a write is allowed, it has to happen under the same lock as the write. Reading first and writing later is fine for one person, and wrong as soon as there are two.
