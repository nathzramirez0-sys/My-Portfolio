ThesisFlow · 7 Oct 2026

Testing my security rules found two holes

ThesisFlow's Firebase security rules decide who may read and change what. Writing 59 tests for them turned up two mistakes I had missed.

ThesisFlow keeps each thesis group's chapters, drafts, tasks and feedback in Firebase. The app hides buttons people can't use, but the real protection is the security rules on the server: only leaders and advisers approve chapters, members move only their own tasks, only advisers post feedback, and nobody outside a group sees anything in it.

How I tested them

Rules are code, so I tested them like code. The suite runs against the Firestore and Storage emulators with a seeded group of four people: a leader, a member, an adviser and an outsider. Each of the 59 tests writes the same fields, batches and server timestamps the app's repositories write, so a rule that passes a test passes the app, and a rule that refuses the app fails a test.

Hole one: a draft that could vanish

Drafts are kept as version history: every upload is a new version in Firestore, with its file in Storage. The Storage rules let whoever uploaded a draft delete their own file. Firestore would still list that version, now pointing at nothing. The rules no longer allow it; draft files are removed only by the server's clean-up functions.

Hole two: a check that never ran

The rule that stops anyone overwriting an existing file was written for updates. But the Storage emulator treats every upload as a create, even over a file that is already there, so in the tests the overwrite went straight through. The check now sits on create as well, guarded so it only applies when a file already exists.

Keeping them honest

The rule tests now run in GitHub Actions on every push, next to the 142 unit tests and the builds, so a change to the rules that opens a gap fails before it ships.

What I took from it

Reading rules carefully wasn't enough: both mistakes looked reasonable on the page. Running them against real data, as real users, is what showed what they actually allowed.
