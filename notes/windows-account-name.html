Cable Manager · 30 Oct 2026

The letter that stopped my database

Going live on the office computer, the database refused to start. The cause was one letter in the Windows account's name.

Cable Manager installs as one Windows setup file that brings its own web server, database and PHP. On every start, a launcher writes their configuration files, and each one contains the path to the data folder in the signed-in user's AppData.

What went wrong

On the provider's office computer, the database wouldn't start. Its log said it couldn't change into the data folder: the path it had been given had a question mark where a letter should be. The Windows account's name contained an ñ, which is common in Filipino names, and the launcher had written the configuration files as ASCII. ASCII has no ñ, so it became "?", and the folder the database was told to use didn't exist.

It never showed up on my laptop or in testing, because every account I had used was plain English letters. One more detail made it worse: the step that creates the database got the path on its command line, not from the file, so it had already made a half-finished data folder. A later start would have found that folder and skipped first-run setup, leaving a database with no tables.

The fix

The launcher now checks whether the path is plain ASCII before writing it anywhere. If it isn't, it uses Windows' short name for the same folder, the 8.3 kind made only of plain letters. If the drive doesn't keep short names, it falls back to a folder under ProgramData. Paths that were already plain ASCII, which every working install had, are left exactly as they were.

Testing it without touching the real system

The office computer was in use, so I tested against the packaged build on ports of its own, with a made-up account folder whose name had an ñ, and a second one that exercised the fallback. Both came out as plain ASCII paths, and the database started. The fixed installer went onto the office computer the same day, and it has run there since.

What I took from it

Every place text crosses into a file or another program is a place encoding can break. And test data should look like real users: in the Philippines, that includes names with ñ.
