Capstone project · Android tablet app · 2026

FergBentables

An offline app for a showroom counter, in use at a showroom. It keeps the showroom's buyers, their orders, every payment towards them and its stock, follows each order to delivery, prints an order slip or a paid receipt, backs everything up to an encrypted file, and hands the office its records in Excel.

The brief

One tablet at the counter had to be the whole system: who the buyers are, what they bought, where each order stands, a receipt for the paid ones, and files the office can open. No internet, no server and no logins, because the shop has none of them.

Decisions that mattered

  • Money that never rounds

    Prices are BigDecimal in the code and whole centavos in the database, so totals and SQL sums are exact. A third decimal is refused, never rounded away.

  • Stock that can't go wrong

    An order and the stock it takes are saved in one transaction. Editing an order moves only the difference, overselling refuses the whole order, and every movement is credited to whoever made it.

  • What is paid, and what is still due

    Every payment towards an order is recorded, downpayments included. An order with a balance prints an order slip showing what is paid and what is due; a fully paid one prints its receipt.

  • An Excel file a phone will open

    Excel for Android called the exports "password-protected". The cause was how the file was zipped, so the app now writes every part with its size and checksum in its own header, the way Excel does, and a test checks it.

  • The shop's only copy

    The tablet holds the only copy, so everything, photos included, backs up to one encrypted file (AES-256-GCM, each chunk tied to its place, so a cut or reordered file is refused). A restore checks the password and the file before changing anything, and puts the old records back if it fails halfway. Six database versions, every migration tested on real SQLite.

  • A lock that can't be rushed

    An optional PIN of 4 to 6 digits, kept only as a salted PBKDF2 hash. It asks again after the app has been away for as long as the operator chooses, and five wrong tries make it wait 30 seconds.

  • A small release that still works

    R8 shrinks the APK from about 70 MB to about 14 MB. A missing keep rule doesn't fail the build, it fails an export at the counter, so every release is checked by hand: an export and a receipt.

  • Built from what the staff asked for

    Facebook contacts, a Payment Status column, download to the device, inventory and restock reminders all came from the people using it, shipped in rounds as they asked.
